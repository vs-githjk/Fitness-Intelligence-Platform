# Design authority index

Per-screen and system design authorities for Vytal. Read these alongside the
binding [product-principles.md](../product-principles.md) before changing any visual
surface.

## Authority order

1. **[product-principles.md](../product-principles.md)** — binding experience and
   boundary principles. Nothing below relaxes a boundary principle.
2. **[visual-identity-v2-iron-editorial.md](visual-identity-v2-iron-editorial.md)** —
   **the frozen visual identity and design system** (Iron Editorial, approved
   2026-08-12): registers, color/type contracts, illustration and media systems,
   per-surface direction, and the Experience Cycle 2 plan. Design authority for Cycle 2;
   supersedes the earlier exploration/convergence artifacts. Statuses `[FROZEN]` /
   `[FLEX]` / `[FUTURE]` / `[DECISION]` / `[LAW]` are binding.
3. **Per-screen content specs** — e.g. [trainee-today.md](trainee-today.md) (Today
   content, hierarchy, acceptance criteria). Remain binding on content where Visual
   Identity v2 amends only presentation.
4. **[components.md](components.md)** — the Morning Brief component reference (as-built).
5. **[../design-system.md](../design-system.md)** — the **as-built v0.5.0 (v1)** system;
   accurate for unmigrated surfaces, superseded surface-by-surface as Cycle 2 migrates
   each screen.

## Governance rule

Before modifying trainee/coach visual experience, shell, navigation, theme, typography,
media presentation, or a Cycle-2 surface, read Visual Identity v2 **and** the applicable
per-screen/domain specification. Only founder/product may change a `[FROZEN]` or `[LAW]`
item; changes are recorded in Visual Identity v2 §36 and, for domain contracts,
[../decisions/README.md](../decisions/README.md).
